## Задача и результат

У обычного AI-чата короткая память и мало связи с реальной работой. А помощник с доступом к инструментам может сделать слишком много: перепутать проекты, повторить действие после сбоя или принять свою догадку за разрешение.

В исходниках реализованы общий разговор для браузера и iPhone, голосовой ввод и ответы, история с настоящими авторами сообщений и подтверждения внутри чата. Это результат по возможностям продукта; экономия времени и число пользователей здесь не заявляются без измерений.

## Мой вклад

Я определяю роли помощника, правила взаимодействия, границы памяти и условия выполнения действий. Отвечаю за логику продукта и конструкцию системы: какие решения помощник принимает сам, где обязан спросить и как пользователь понимает происходящее.

В разработке использую AI-инструменты; продуктовые и архитектурные решения принимаю сам.

## Engineering highlights

- **Не повторять неизвестное.** Если исполнитель потерял ответ, это не означает, что действие не произошло. Резервный провайдер подключается только при допустимом сбое до выполнения.
- **Память с происхождением.** Факт хранит ссылки на сообщения. Проверка владельца, версии и запись выполняются в одной транзакции — устаревший ответ модели не перезаписывает более свежую память.
- **Делегировать по делу.** Координатор привлекает нужные роли. Ограничения вызовов и проверка циклов не дают переписке агентов стать бесконечной.

## Архитектура и стек

| Слой | Реализация |
|---|---|
| Интерфейсы | Telegram, Preact, SwiftUI; браузерный чат |
| Backend / AI | Bun, TypeScript, координатор ролей, Claude Agent SDK |
| Данные | SQLite WAL; диалоги, задания, согласования, память проектов |
| Инфраструктура | systemd, GitHub Actions, отдельный мост выполнения |

Диалог принадлежит владельцу; связь с проектом хранится отдельно. Память диалога имеет ревизию, предложение на публикацию фиксирует её снимок, а подтверждённый факт сохраняет происхождение. Новые таблицы добавляются без изменения существующих диалогов.

## Quick start

```bash
# Requires Bun. These checks use local fixtures, not provider accounts.
git clone https://github.com/kevinscott66/ai-agents.git
cd ai-agents/agent
bun test tests/native-knowledge.test.ts tests/mac-provider-fallback.test.ts
```

Для UI: `cd miniapp && npm install && npm run build`. `npm run dev` запускает frontend; реальные данные требуют авторизованного backend. Для помощника установите зависимости agent и заполните `agent/.env.example` своими аккаунтами провайдеров и Telegram. Не используйте рабочий токен для экспериментов.

## Проверки


## Развёртывание, мониторинг и API

Сервис и панель разворачиваются отдельно от подписанной iPhone-сборки. Очереди, журнал действий и health-состояния помогают понять, что выполнено, что ожидает решения и что требует вмешательства. Секреты и рабочие базы не входят в публичный репозиторий.

```bash
# With a locally configured service:
curl --fail http://127.0.0.1:8787/api/health
```

Порт зависит от локальной конфигурации. Native и Telegram API имеют отдельную аутентификацию; ответ health не означает доступ к чатам или инструментам.

## Безопасность и ограничения

Для работы нужны учётные записи провайдеров и настройка владельца. Публичного доступа к рабочим чатам нет. Виртуальный офис 2D/3D и GitHub MCP находятся в отдельной ветке разработки; банковское исполнение не заявляется как готовая возможность.

SQLite упрощает эксплуатацию и позволяет атомарно обновлять память, но требует внимания к длительным операциям в одном процессе. Голос построен как запись → распознавание → ответ → синтез: это проще контролировать, но не одновременный разговор в обе стороны.

Политика раскрытия уязвимостей: [SECURITY.md](SECURITY.md).
