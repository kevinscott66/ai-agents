# Переключение команды между Claude и Codex

Область: все вызовы через `runWithTools` и `callAnthropic`, включая делегирование ролям, компактор и self-diag. `SPAWN_ROLE_PROVIDER` оставляем `internal`: это отдельный переключатель очереди, а не модель всей команды.

## Конфигурация

- `AGENT_PROVIDER=claude` (по умолчанию): существующие Claude SDK/API и их настройки без изменений.
- `AGENT_PROVIDER=codex`: Codex CLI, без автоматического fallback на Claude.
- `CODEX_AUTH_HOME`: отдельный каталог авторизации CLI, доступный только пользователю сервиса.
- `CODEX_BIN`: обязательный абсолютный путь CLI 0.149.0; версия проверяется перед каждым запуском, другая версия отклоняется.
- `CODEX_MODEL`: необязательная модель; пустое значение выбирает первую доступную по приоритету модель встроенного каталога CLI. Неизвестные каталогу модели отклоняются.

Переключение требует перезапуска `agent-team`; применять между активными задачами. Для возврата установить `AGENT_PROVIDER=claude` и перезапустить сервис. Не удалять Claude OAuth/API credentials или менять `USE_AGENT_SDK` при переключении.

## Границы адаптера

Codex выдаёт структурированный ответ с предложениями вызовов. Выполняет их существующий dispatcher с ACL, ограничениями ролей и подтверждениями. CLI запускается в одноразовом каталоге без унаследованных секретов сервиса, пользовательского config и встроенных инструментов. Для этого копия встроенного каталога CLI получает apply_patch_tool_type=null; планировщик и request_user_input отключены отдельно. Локальный mock Responses endpoint подтвердил tools:[] для CLI 0.149.0. История и память остаются в существующем хранилище. Файлы запроса удаляются по завершении.

Дедлайн вызова — 180 секунд, до 8 предложений инструментов, размер потока до 2 MiB. Завершённые генерации учитываются в бюджете даже при отклонении ответа валидатором. Отсутствующее/повторное событие completion отклоняется; завершающая JSON-строка без перевода строки учитывается. Чтение файла ответа ограничено до выделения большого буфера; сумма изображений ограничена 20 MiB, MIME проверяется. Автоматических повторов через другую модель нет.

**Ограничения:** Anthropic server-side web_search не переносится; доступны клиентские инструменты команды. CLI не предоставляет подтверждённого аналога жёсткого `max_tokens`: желаемый лимит передаётся инструкции, действуют дедлайн, ограничение размера ответа и дневной бюджет. Это не тождественно API-лимиту генерации. Нужны live-проверки конкретной модели и её JSON output schema до активации.

## Активация

1. Пройти PR и независимую проверку inference/tool boundary.
2. Обеспечить место для CLI на сервере. При попытке установки 2026-09-15 npm завершил распаковку с ENOSPC; незавершённая установка удалена. Сервис Claude остался active.
3. Установить CLI в отдельный каталог. Выбрать метод авторизации с владельцем (вопрос ожидает ответа). Для подписки выполнить `codex login --device-auth` от пользователя сервиса с выделенным CODEX_HOME. Не копировать auth.json в Git или сообщения.
4. Выполнить read-only live smoke текстового ответа, предложения разрешённого инструмента, учёта usage и явного отказа при недоступной модели. Не отправлять реальные заказы/переводы/сообщения при smoke.
5. Развернуть проверенные файлы адаптера и env-настройки. После завершения активных задач переключить AGENT_PROVIDER на codex, перезапустить и проверить ответ лидера/делегированной роли.
6. Проверить возврат на claude и повторное переключение на codex. При проблеме оставить claude.

Официальный CLI workflow: https://developers.openai.com/codex/noninteractive/
